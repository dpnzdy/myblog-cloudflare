# 콘텐츠 데이터 구조

## 1. 기본 원칙

- 콘텐츠 원본은 저장소의 Markdown/MDX 파일로 관리한다.
- Astro Content Collections와 스키마 검증을 사용해 빌드 전에 필수값과 형식을 확인한다.
- 본문과 메타데이터는 분리하되 화면에 표시되는 사실과 구조화 데이터가 동일한 원본을 사용하게 한다.
- 날짜는 ISO 8601 형식으로 저장하고 사이트에서는 한국어 표기로 렌더링한다.
- 열거형과 참조 키는 안정적인 영문 소문자를 사용한다.

## 2. 콘텐츠 컬렉션

### `posts`

일반 글, 튜토리얼, 가이드, 리뷰를 관리하는 핵심 컬렉션이다.

| 필드 | 형식 | 필수 | 설명 |
|---|---|---:|---|
| `title` | 문자열 | 예 | 페이지 H1과 메타 제목의 기본값 |
| `description` | 문자열 | 예 | 검색 결과와 카드에 쓰는 고유 요약 |
| `slug` | 문자열 | 예 | 영문 소문자·숫자·하이픈 기반 영구 경로 |
| `contentType` | 열거형 | 예 | `article`, `tutorial`, `review`, `comparison` |
| `publishedAt` | 날짜·시간 | 예 | 최초 공개 시점 |
| `updatedAt` | 날짜·시간 | 아니요 | 의미 있는 최종 수정 시점 |
| `draft` | 불리언 | 예 | 기본값은 안전하게 초안으로 설정 |
| `author` | 작성자 키 | 예 | `authors` 컬렉션 참조 |
| `category` | 카테고리 키 | 예 | 대표 카테고리 하나 |
| `tags` | 문자열 배열 | 예 | 중복 없는 정규화 태그, 빈 배열 허용 |
| `summary` | 문자열 | 예 | 본문 상단 핵심 답변 |
| `heroImage` | 이미지 참조 | 아니요 | 대표 이미지 |
| `heroAlt` | 문자열 | 조건부 | 대표 이미지가 있으면 필수 |
| `heroCaption` | 문자열 | 아니요 | 설명과 출처 표기 |
| `featured` | 불리언 | 아니요 | 홈·허브 추천 후보 |
| `readingTimeOverride` | 숫자 | 아니요 | 자동 계산이 부정확한 경우만 사용 |
| `canonicalUrl` | URL | 아니요 | 외부 선공개 등 예외 상황에만 사용 |
| `noindex` | 불리언 | 아니요 | 특수한 공개 페이지의 색인 제외 |
| `series` | 시리즈 키 | 아니요 | 연재물 참조 |
| `seriesOrder` | 양의 정수 | 조건부 | 시리즈가 있으면 사용 |
| `prerequisites` | 문자열 배열 | 아니요 | 사전 지식 또는 요구 조건 |
| `testedOn` | 문자열 배열 | 아니요 | OS, 제품, 소프트웨어 버전 등 테스트 환경 |
| `sources` | 출처 배열 | 아니요 | 제목, URL, 접근일, 출처 유형 |
| `disclosure` | 고지 객체 | 예 | 광고·제휴·제품 제공 상태 |
| `review` | 리뷰 객체 | 조건부 | 리뷰·비교 글에 필수 |
| `faq` | 질문·답변 배열 | 아니요 | 본문에서도 확인 가능한 항목만 사용 |

### `authors`

| 필드 | 형식 | 필수 | 설명 |
|---|---|---:|---|
| `id` | 문자열 | 예 | 안정적인 작성자 키 |
| `name` | 문자열 | 예 | 표시 이름 |
| `bio` | 문자열 | 예 | 전문성과 경험 요약 |
| `avatar` | 이미지 참조 | 아니요 | 프로필 이미지 |
| `expertise` | 문자열 배열 | 예 | 전문 분야 |
| `links` | 링크 배열 | 아니요 | 검증 가능한 외부 프로필 |

### `categories`

| 필드 | 형식 | 필수 | 설명 |
|---|---|---:|---|
| `id` | 문자열 | 예 | `reviews`, `ubuntu`, `python`, `codex` 중 하나 |
| `name` | 문자열 | 예 | 한국어 표시명 |
| `description` | 문자열 | 예 | 카테고리 페이지 고유 설명 |
| `order` | 정수 | 예 | 내비게이션 순서 |

### `pages`

소개, 편집 원칙, 정책처럼 게시 날짜 중심이 아닌 정적 문서를 관리한다.

| 필드 | 형식 | 필수 | 설명 |
|---|---|---:|---|
| `title` | 문자열 | 예 | 페이지 제목 |
| `description` | 문자열 | 예 | 고유 요약 |
| `slug` | 문자열 | 예 | 고정 경로 |
| `updatedAt` | 날짜 | 예 | 최종 갱신일 |
| `noindex` | 불리언 | 아니요 | 기본값 false |

## 3. 중첩 객체

### 광고·제휴 고지 `disclosure`

| 필드 | 형식 | 필수 | 설명 |
|---|---|---:|---|
| `hasAffiliateLinks` | 불리언 | 예 | 제휴 링크 포함 여부 |
| `isSponsored` | 불리언 | 예 | 금전적 협찬 여부 |
| `productProvided` | 불리언 | 예 | 제품 무상 제공 여부 |
| `provider` | 문자열 | 조건부 | 협찬 또는 제공 주체 |
| `note` | 문자열 | 아니요 | 표준 문구 외 추가 설명 |

세 값이 모두 false여도 객체 자체는 명시해 누락과 비해당을 구분한다.

### 리뷰 정보 `review`

| 필드 | 형식 | 필수 | 설명 |
|---|---|---:|---|
| `productName` | 문자열 | 예 | 정확한 제품명 |
| `brand` | 문자열 | 예 | 제조사 또는 브랜드 |
| `model` | 문자열 | 아니요 | 모델 번호 |
| `rating` | 숫자 | 예 | 사이트에서 정한 동일 척도의 점수 |
| `ratingScale` | 숫자 | 예 | 예: 5 또는 10 |
| `priceAtReview` | 금액 객체 | 아니요 | 통화, 금액, 확인일 |
| `pros` | 문자열 배열 | 예 | 실제 본문에 설명된 장점 |
| `cons` | 문자열 배열 | 예 | 실제 본문에 설명된 단점 |
| `bestFor` | 문자열 배열 | 예 | 추천 대상 |
| `notFor` | 문자열 배열 | 아니요 | 비추천 대상 |
| `testedFrom` | 날짜 | 아니요 | 테스트 시작일 |
| `testedUntil` | 날짜 | 아니요 | 테스트 종료일 |

가격은 변동 가능하므로 확인일을 함께 표시하며 최신 가격인 것처럼 단정하지 않는다.

### 출처 `sources`

| 필드 | 형식 | 필수 | 설명 |
|---|---|---:|---|
| `title` | 문자열 | 예 | 사람이 이해할 수 있는 출처명 |
| `url` | URL | 예 | 원문 URL |
| `publisher` | 문자열 | 아니요 | 발행 기관 |
| `accessedAt` | 날짜 | 아니요 | 확인일 |
| `type` | 열거형 | 예 | `official`, `research`, `measurement`, `reference` |

## 4. 본문 구조 권장안

일반 가이드와 튜토리얼:

1. 핵심 답변
2. 적용 대상과 전제 조건
3. 테스트 환경 및 버전
4. 단계별 설명
5. 결과 확인
6. 오류와 해결 방법
7. 결론
8. 출처와 변경 이력

제품 리뷰와 비교:

1. 한눈에 보는 결론
2. 제품 및 테스트 조건
3. 평가 기준
4. 항목별 결과
5. 장점과 단점
6. 대안과 비교
7. 추천 대상과 비추천 대상
8. 가격 확인일과 제휴 고지
9. 출처와 변경 이력

## 5. 파일 및 자산 규칙

- 콘텐츠 파일명과 `slug`는 가능하면 일치시킨다.
- 게시물 이미지는 해당 글과 가까운 디렉터리에 두거나 일관된 자산 디렉터리 규칙을 사용한다.
- 이미지 파일명은 내용을 설명하는 영문 이름을 사용한다.
- 원본 이미지와 생성된 파생 이미지를 구분한다.
- 이미지 출처와 사용 권한을 기록한다.
- MDX 컴포넌트는 허용 목록으로 제한해 문서마다 표현 방식이 달라지는 것을 막는다.

## 6. 검증 규칙

- 제목과 설명은 비어 있지 않고 사이트 내에서 중복되지 않아야 한다.
- `updatedAt`은 `publishedAt`보다 빠를 수 없다.
- 미래 발행 글과 초안은 프로덕션 출력에서 제외한다.
- 카테고리와 작성자 참조는 실제 항목을 가리켜야 한다.
- 태그는 중복과 앞뒤 공백이 없어야 한다.
- 대표 이미지가 있으면 대체 텍스트가 있어야 한다. 순수 장식 이미지는 별도 규칙으로 빈 대체 텍스트를 허용한다.
- 리뷰 점수는 0보다 크고 `ratingScale` 이하여야 한다.
- 협찬 또는 제품 제공 상태가 true이면 제공자를 필수로 한다.
- 외부 URL은 허용된 프로토콜을 사용해야 한다.
- 동일 slug와 생성 URL 충돌은 빌드 오류로 처리한다.

## 7. 파생 데이터

다음 값은 직접 입력하지 않고 빌드 시 계산하는 것을 원칙으로 한다.

- 예상 읽기 시간
- 본문 목차
- 단어 수
- 관련 글 후보
- 카테고리·태그별 글 수
- 이전 글·다음 글
- 구조화 데이터 JSON
- RSS 항목
- 사이트맵의 최종 수정일

# 개인 기술 블로그 요구사항

## 1. 문서 목적

이 문서는 Astro, TypeScript, Markdown/MDX를 사용해 제작하고 Cloudflare Pages에 배포할 개인 기술 블로그의 제품 범위와 품질 기준을 정의한다.

## 2. 서비스 목표

- IT 제품 리뷰와 Ubuntu, Python, Codex 관련 실용 콘텐츠를 축적한다.
- 검색 엔진과 AI 답변 시스템이 내용을 정확히 발견하고 인용할 수 있게 한다.
- 광고와 제휴 링크를 독자 신뢰를 해치지 않는 방식으로 운영해 수익화한다.
- 운영자 한 명이 글 작성, 수정, 배포, 성과 측정을 지속할 수 있게 한다.

## 3. 대상 독자

- IT 제품을 구매하기 전에 실제 사용 경험과 비교 정보를 찾는 사람
- Ubuntu 설치, 설정, 문제 해결 방법이 필요한 초급·중급 사용자
- Python 예제와 오류 해결법을 찾는 개발자 또는 학습자
- Codex의 설정, 활용법, 개발 워크플로를 찾는 사용자

기본 콘텐츠 언어는 한국어로 한다. 다국어는 초기 범위에서 제외하되, 향후 언어별 URL을 도입할 수 있도록 경로와 데이터 구조를 확장 가능하게 설계한다.

## 4. 기능 요구사항

### 4.1 콘텐츠 작성 및 발행

- 글은 Markdown 또는 MDX 파일로 관리한다.
- 초안은 빌드 결과와 사이트맵, RSS에서 제외한다.
- 글마다 제목, 설명, 발행일, 수정일, 작성자, 카테고리, 태그, 대표 이미지, 공개 상태를 관리한다.
- 리뷰 글에는 평가 대상, 제조사, 장단점, 평점, 제휴 여부를 추가로 기록할 수 있어야 한다.
- 게시물 URL은 영구적인 영문 슬러그를 사용하며 발행 뒤 임의로 변경하지 않는다.
- 변경이 불가피하면 기존 URL에서 새 URL로 영구 리디렉션한다.
- 코드 블록, 표, 이미지, 각주, 인용문, 목차를 지원한다.
- 글의 이전 글·다음 글과 관련 글을 표시한다.

### 4.2 탐색

- 홈에서 최신 글, 주요 카테고리, 추천 글을 확인할 수 있어야 한다.
- 전체 글 목록을 최신순으로 탐색할 수 있어야 한다.
- 카테고리 및 태그별 글 목록을 제공한다.
- 제목, 설명, 카테고리, 태그를 대상으로 하는 검색을 제공한다.
- 상단 내비게이션과 푸터에서 주요 페이지로 이동할 수 있어야 한다.
- 모바일과 키보드 환경에서도 메뉴와 검색을 사용할 수 있어야 한다.

### 4.3 구독 및 배포

- RSS 피드를 제공한다.
- XML 사이트맵과 robots.txt를 제공한다.
- 각 게시물에 복사 가능한 정규 URL과 공유용 메타데이터를 제공한다.
- 404 페이지를 제공한다.

### 4.4 수익화

- 광고 영역은 본문과 시각적으로 구분하고 레이아웃 이동을 방지할 고정 공간을 확보한다.
- 제휴 링크가 포함된 글과 링크 근처에 경제적 이해관계를 명확히 표시한다.
- 제품 제공, 원고료, 협찬 여부도 글 상단에 표시한다.
- 광고 차단이나 광고 스크립트 실패가 콘텐츠 열람을 막지 않아야 한다.
- 개인정보 처리방침, 쿠키 정책, 제휴·광고 고지 페이지를 제공한다.
- 동의가 필요한 분석·광고 스크립트는 동의 상태에 따라 로드한다.

## 5. SEO 요구사항

- 모든 색인 가능 페이지에 고유한 title, meta description, canonical URL을 제공한다.
- 페이지 유형에 맞는 Open Graph 및 소셜 공유 메타데이터를 제공한다.
- 게시물에는 Article 또는 BlogPosting 구조화 데이터를 제공한다.
- 제품 리뷰에는 실제 본문과 일치하는 경우에만 Product, Review 구조화 데이터를 제공한다.
- 사이트에는 WebSite, 운영자 소개에는 Person 또는 Organization, 이동 경로에는 BreadcrumbList 구조화 데이터를 사용한다.
- 구조화 데이터의 제목, 날짜, 작성자, 평점 등은 화면에 표시되는 내용과 일치해야 한다.
- 한 페이지에는 의미가 명확한 H1 하나를 두고 제목 계층을 순서대로 사용한다.
- 대표 이미지와 본문 이미지에 의미 있는 대체 텍스트, 크기, 캡션을 지원한다.
- 태그 조합, 검색 결과, 페이지네이션 등 중복 가능 페이지의 색인 정책을 명시한다.
- 삭제·이동된 콘텐츠는 적절한 404, 410 또는 301 상태로 처리한다.

## 6. AEO 및 GEO 요구사항

- 글 첫 부분에 질문 또는 문제와 이에 대한 간결한 요약 답변을 제공할 수 있어야 한다.
- 사용 조건, 전제, 버전, 테스트 날짜를 명시한다.
- 절차형 글은 번호가 있는 단계와 예상 결과를 함께 제공한다.
- 비교·리뷰 글은 선정 기준, 테스트 방법, 장점, 단점, 추천 대상과 비추천 대상을 명시한다.
- 주장에는 공식 문서, 원문 자료, 측정 결과 등 확인 가능한 출처를 연결한다.
- 작성자 소개, 전문 분야, 수정 이력, 편집·리뷰 정책을 공개한다.
- FAQ는 실제 본문에서 답한 질문만 포함하며, FAQ 구조화 데이터는 검색엔진 정책과 표시 내용에 부합할 때만 사용한다.
- AI 크롤러 정책은 robots.txt에서 명시적으로 관리하되 검색 색인 정책과 별도로 결정한다.
- 핵심 정보가 클라이언트 JavaScript 실행 없이 생성된 HTML에 포함되어야 한다.

## 7. 비기능 요구사항

### 7.1 성능

- 정적 HTML을 기본으로 하고 필요한 부분에만 클라이언트 JavaScript를 사용한다.
- 이미지는 반응형 크기, 최신 포맷, 지연 로딩을 지원한다. 첫 화면의 핵심 이미지는 예외적으로 우선 로드할 수 있다.
- 프로덕션 기준 Core Web Vitals 목표는 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하로 한다.
- 성능 예산의 초기 목표는 일반 게시물 페이지 압축 전 JavaScript 100KB 이하, 초기 로드 이미지 500KB 이하로 한다. 예외는 문서화한다.

### 7.2 접근성

- WCAG 2.2 AA 수준을 목표로 한다.
- 모든 기능은 키보드로 사용할 수 있어야 한다.
- 명확한 포커스 표시, 본문 바로가기, 적절한 랜드마크와 레이블을 제공한다.
- 텍스트 및 UI 대비를 충족하고 200% 확대에서도 콘텐츠와 기능이 손실되지 않아야 한다.
- 동작 감소 설정과 다크 모드를 고려한다.

### 7.3 보안 및 개인정보

- HTTPS만 사용한다.
- 외부 스크립트와 임베드는 최소화하고 보안 헤더와 Content Security Policy 적용 가능성을 검토한다.
- 비밀키와 API 키를 저장소나 정적 번들에 포함하지 않는다.
- 수집하는 데이터, 목적, 보관 기간, 제3자 제공을 정책에 공개한다.
- 문의 기능을 추가할 경우 스팸 방지와 개인정보 최소 수집을 적용한다.

### 7.4 호환성 및 운영성

- 최신 안정 버전의 Chrome, Edge, Firefox, Safari와 주요 모바일 브라우저를 지원한다.
- 320px 너비부터 대형 데스크톱까지 가로 스크롤 없이 동작해야 한다. 코드와 표는 제한된 영역에서 자체 스크롤을 허용한다.
- 빌드 실패 시 배포하지 않으며 미리보기 배포에서 검수할 수 있어야 한다.
- 콘텐츠 오류가 어느 파일의 어떤 필드에서 발생했는지 빌드 단계에서 알 수 있어야 한다.

## 8. 분석 및 성과 측정

- 최소 수집 원칙에 맞는 웹 분석 도구를 선택한다.
- 검색 노출, 클릭, 색인 상태, Core Web Vitals를 측정한다.
- 내부 검색어, 제휴 링크 클릭, 광고 위치별 성과를 개인정보를 침해하지 않는 범위에서 측정한다.
- 핵심 지표는 자연 검색 방문, 유효 색인 페이지, 상위 글 체류·스크롤, 제휴 클릭률, 광고 수익, 재방문으로 한다.

## 9. 초기 범위 제외

- 회원가입, 로그인, 댓글 계정 시스템
- 서버 데이터베이스와 자체 CMS
- 결제 및 유료 구독
- 실시간 개인화 추천
- 다국어 콘텐츠 제공
- 네이티브 모바일 앱

## 10. 완료 조건

- 필수 페이지와 콘텐츠 분류가 사이트맵대로 생성된다.
- 샘플 게시물로 목록, 상세, 분류, 검색, RSS, 사이트맵 흐름을 검증한다.
- 접근성, 성능, SEO, 콘텐츠 스키마, 배포 테스트가 `06-test-criteria.md`의 출시 기준을 통과한다.
- 운영 정책과 광고·제휴 고지가 공개된 상태에서 프로덕션 도메인으로 배포된다.

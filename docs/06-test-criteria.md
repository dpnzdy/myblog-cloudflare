# 테스트 기준

## 1. 테스트 원칙

- 로컬 개발 서버만이 아니라 프로덕션 빌드 결과와 Cloudflare Pages 미리보기에서 검증한다.
- 자동 검사는 반복 가능한 회귀 방지에 사용하고, 콘텐츠 품질과 시각적 사용성은 수동 검수를 병행한다.
- 출시 차단 결함은 개인정보 침해, 콘텐츠 접근 불가, 빌드 실패, 잘못된 색인, 중대한 접근성 문제, 수익 고지 누락을 포함한다.

## 2. 콘텐츠 스키마

### 자동 테스트

- 필수 필드가 없는 콘텐츠는 빌드에 실패한다.
- 잘못된 날짜, URL, 열거형, 작성자·카테고리 참조는 빌드에 실패한다.
- 중복 slug와 생성 URL 충돌은 빌드에 실패한다.
- 대표 이미지가 있는데 대체 텍스트가 없으면 실패한다.
- 리뷰 점수가 척도 밖이면 실패한다.
- 협찬 또는 제품 제공 글에서 제공자가 없으면 실패한다.
- 초안과 미래 발행 글은 프로덕션 출력, RSS, 사이트맵에 포함되지 않는다.

### 수동 검수

- 제목, 요약, 본문, 구조화 데이터의 사실이 서로 일치한다.
- 튜토리얼의 명령과 절차를 문서에 적힌 환경에서 재현할 수 있다.
- 리뷰의 장단점과 점수가 본문 근거에 의해 뒷받침된다.
- 외부 자료와 이미지의 출처 및 사용 권한이 기록되어 있다.

## 3. 기능 테스트

- 홈, 글 목록, 모든 주제 허브, 카테고리, 태그, 게시물, 정책 페이지가 정상 응답한다.
- 헤더, 푸터, 모바일 메뉴의 모든 링크가 올바른 경로로 이동한다.
- 페이지네이션에서 누락과 중복 없이 모든 공개 글에 도달할 수 있다.
- 검색은 제목, 설명, 카테고리, 태그에서 기대한 결과를 반환한다.
- 빈 검색어와 결과 없음 상태가 명확하다.
- 관련 글과 이전·다음 글이 비공개 콘텐츠를 노출하지 않는다.
- 존재하지 않는 URL은 맞춤 404 화면과 실제 404 상태를 반환한다.
- 테마 선택은 시스템 설정을 존중하며 새로고침 후 의도한 방식으로 유지된다.

## 4. 반응형 및 브라우저 테스트

검증 너비의 최소 집합은 320px, 375px, 768px, 1024px, 1440px로 한다.

- 일반 본문에서 의도하지 않은 가로 스크롤이 없다.
- 긴 URL, 긴 제목, 긴 코드 줄, 넓은 표가 레이아웃을 깨뜨리지 않는다.
- 이미지와 광고가 컨테이너 너비를 넘지 않는다.
- 모바일 메뉴와 검색을 터치 및 키보드로 조작할 수 있다.
- 최신 안정 버전의 Chrome, Edge, Firefox, Safari에서 핵심 흐름이 동작한다.
- 실제 iOS Safari와 Android Chrome 또는 이에 준하는 원격 테스트 환경에서 대표 페이지를 확인한다.

## 5. 접근성 테스트

- 자동 접근성 검사에서 심각 또는 중대 위반이 0건이다.
- 키보드만으로 모든 링크, 메뉴, 검색, 테마 전환을 사용할 수 있다.
- 포커스 순서가 시각적 흐름과 일치하고 포커스 표시가 보인다.
- 본문 바로가기가 작동한다.
- 페이지마다 고유하고 목적을 설명하는 제목이 있다.
- H1은 주요 콘텐츠 기준 하나이며 제목 단계가 논리적이다.
- 폼 요소와 아이콘 버튼에 접근 가능한 이름이 있다.
- 정보성 이미지에는 적절한 대체 텍스트가 있고 장식 이미지는 보조기술에서 제외된다.
- 일반 텍스트와 UI 구성요소가 WCAG 2.2 AA 대비 기준을 충족한다.
- 200% 확대와 텍스트 확대에서 정보 또는 기능이 손실되지 않는다.
- 동작 감소 설정에서 불필요한 애니메이션이 줄어든다.

## 6. SEO, AEO, GEO 테스트

- 색인 가능 페이지마다 고유 title, description, canonical이 있다.
- canonical과 Open Graph URL은 프로덕션 절대 URL이며 미리보기 도메인을 포함하지 않는다.
- 검색 페이지, 초안, 의도적으로 제외한 페이지에 올바른 robots 정책이 적용된다.
- XML 사이트맵에는 200 응답의 canonical 페이지만 포함된다.
- robots.txt가 사이트맵 위치를 가리키며 의도하지 않은 전체 차단이 없다.
- RSS가 유효하고 최신 공개 글과 절대 URL을 포함한다.
- 게시물의 구조화 데이터가 검증 도구에서 오류 없이 통과한다.
- 리뷰 구조화 데이터는 리뷰 글에만 존재하고 표시된 제품, 평점, 작성자와 일치한다.
- 이동 경로 구조화 데이터와 화면의 이동 경로가 일치한다.
- 핵심 답변, 본문, 작성자, 날짜, 출처가 JavaScript 없이 생성된 HTML에서 읽힌다.
- 대표 글에는 질문에 대한 직접 답변, 전제·버전, 근거, 작성자, 수정일이 확인된다.
- 내부 링크 검사 결과 깨진 링크가 없다.

## 7. 성능 테스트

대표 페이지는 홈, 글 목록, 이미지가 많은 리뷰, 코드가 많은 튜토리얼로 선정한다.

### 출시 목표

- Lighthouse 모바일 기준 Performance 90 이상을 목표로 한다.
- Accessibility, Best Practices, SEO는 각각 95 이상을 목표로 한다.
- 실사용 Core Web Vitals 목표는 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하이다.
- 일반 게시물의 압축 전 클라이언트 JavaScript는 100KB 이하를 기본 예산으로 한다.
- 첫 화면 초기 이미지 전송량은 500KB 이하를 기본 예산으로 한다.

실사용 데이터가 없는 출시 전에는 일관된 네트워크·기기 조건의 실험실 측정값을 기준선으로 기록하고, 출시 후 현장 데이터로 보완한다.

### 확인 항목

- 이미지에 크기가 지정되어 레이아웃 이동이 없다.
- 화면 아래 이미지와 임베드는 지연 로드된다.
- 핵심 콘텐츠가 광고 또는 외부 스크립트 완료를 기다리지 않는다.
- 폰트 로딩이 텍스트 표시를 차단하지 않는다.
- 캐시 헤더가 HTML과 해시 자산의 갱신 특성에 맞다.

## 8. 광고, 제휴 및 개인정보 테스트

- 제휴 링크가 있는 모든 글의 상단에 명확한 고지가 있다.
- 제휴 링크 근처에도 독자가 구매 전에 이해할 수 있는 표시가 있다.
- 협찬 및 제품 제공 주체가 콘텐츠 데이터와 화면에 일치한다.
- 광고 영역이 `광고`로 식별되고 본문 링크처럼 보이지 않는다.
- 광고 차단, 느린 로드, 스크립트 오류 상황에서도 글을 읽고 탐색할 수 있다.
- 광고 로드 전후 누적 레이아웃 이동이 전체 CLS 목표를 넘지 않는다.
- 동의가 필요한 쿠키와 스크립트는 동의 전에 설정·실행되지 않는다.
- 동의 거부와 철회가 수락만큼 쉽게 가능하다.
- 개인정보 및 쿠키 정책이 실제 사용 서비스, 목적, 보관 방식과 일치한다.
- 제휴 링크 속성과 새 창 동작이 보안 및 검색 정책에 맞게 설정된다.

## 9. 보안 및 배포 테스트

- 모든 HTTP 요청이 HTTPS의 canonical 호스트로 리디렉션된다.
- 저장소, 생성 파일, 소스맵에 비밀키와 개인정보가 없다.
- 보안 헤더 적용 결과를 기록하고 허용한 외부 출처만 사용한다.
- 외부 링크에 위험한 스킴이 없다.
- 사용자 입력을 표시하는 검색 또는 향후 문의 기능에서 스크립트가 실행되지 않는다.
- 프로덕션 빌드는 깨끗한 환경에서 재현 가능하다.
- 미리보기와 프로덕션의 환경 변수가 분리된다.
- 배포 실패 시 이전 정상 배포가 유지되며 롤백 절차를 실행할 수 있다.
- 301 리디렉션, 404 상태, trailing slash가 문서화된 URL 정책과 일치한다.

## 10. 링크 및 콘텐츠 유지보수 테스트

- 내부 링크 검사는 매 배포 전에 실행한다.
- 외부 링크 검사는 정기적으로 실행하되 일시적 장애와 영구 오류를 구분한다.
- 버전 의존 글은 `testedOn`과 수정일을 기준으로 재검토 목록에 포함된다.
- 품절 제품, 변경된 가격, 종료된 제휴 프로그램을 정기 점검한다.
- 변경된 글은 변경 이력과 의미 있는 `updatedAt`을 반영한다.

## 11. 출시 승인 기준

출시는 다음 조건을 모두 충족해야 한다.

- 프로덕션 빌드와 필수 자동 테스트가 통과한다.
- 치명적·높음 등급 결함이 0건이다.
- 사이트맵의 모든 필수 페이지가 실제 콘텐츠로 준비되어 있다.
- 대표 4개 페이지 유형이 접근성, 반응형, SEO, 성능 검수를 통과한다.
- 초안과 테스트 데이터가 공개 출력에 없다.
- 광고·제휴 고지와 개인정보 관련 정책이 실제 구현과 일치한다.
- 프로덕션 도메인, HTTPS, canonical, RSS, 사이트맵, robots.txt가 확인되었다.
- 배포 직후 점검 및 롤백 담당과 절차가 기록되어 있다.

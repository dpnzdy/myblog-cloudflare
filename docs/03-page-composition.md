# 페이지별 구성

## 1. 공통 레이아웃

모든 페이지는 본문 바로가기, 헤더, 주 콘텐츠, 푸터를 기본 구조로 사용한다. 색인 가능한 페이지에는 고유 title, description, canonical, 소셜 메타데이터를 제공한다.

### 헤더

- 사이트명 또는 로고
- 주요 주제 내비게이션
- 검색 진입점
- 테마 전환
- 모바일 메뉴

### 푸터

- 사이트 한 줄 소개
- 정책 및 고지 링크
- RSS와 연락처
- 저작권 정보

## 2. 홈 `/`

목적은 사이트의 전문 영역과 최신·대표 콘텐츠를 빠르게 전달하는 것이다.

구성 순서:

1. 사이트 가치 제안과 주요 주제 안내
2. 대표 또는 편집자 추천 글
3. 최신 글
4. 리뷰, Ubuntu, Python, Codex 주제 카드
5. 인기 또는 꾸준히 유용한 글
6. 운영자 신뢰 정보와 편집 원칙 링크
7. RSS 또는 구독 안내

홈은 글을 무한히 나열하지 않고 전체 글 페이지로 연결한다.

## 3. 전체 글 `/posts/`

- 페이지 제목과 짧은 설명
- 카테고리 필터 또는 이동 링크
- 최신순 게시물 카드
- 페이지네이션
- 빈 결과 안내

카드에는 제목, 설명, 발행일 또는 수정일, 카테고리, 대표 이미지, 예상 읽기 시간을 표시한다. 정보가 없는 자리표시자는 표시하지 않는다.

## 4. 게시물 상세 `/posts/[slug]/`

### 상단

- 이동 경로
- 카테고리
- H1 제목
- 요약 설명
- 작성자, 발행일, 수정일, 예상 읽기 시간
- 대표 이미지와 캡션·출처
- 협찬·제품 제공·제휴 여부 고지

### 본문

- 질문 또는 문제에 대한 핵심 답변 요약
- 자동 또는 수동 목차
- 제목 계층이 명확한 본문
- 코드 블록, 표, 이미지, 주의사항
- 버전과 테스트 환경
- 외부 근거 및 출처
- 리뷰의 경우 평가 기준, 테스트 방법, 장점, 단점, 추천·비추천 대상
- 실제 자주 묻는 질문이 있을 경우 FAQ

### 하단

- 결론과 다음 행동
- 제휴 링크가 있을 경우 가까운 위치의 반복 고지
- 출처 및 변경 이력
- 작성자 소개
- 태그
- 관련 글
- 이전 글·다음 글

광고는 제목과 핵심 답변 사이를 방해하지 않도록 하고, 본문 흐름을 끊지 않는 사전 정의 위치에만 배치한다.

## 5. 주제 허브 `/reviews/`, `/ubuntu/`, `/python/`, `/codex/`

- 주제 정의와 독자가 얻을 수 있는 가치
- 처음 방문한 독자를 위한 시작 글
- 하위 주제 또는 학습 경로
- 대표 글
- 최신 글
- 관련 카테고리·태그 링크

각 허브는 서로 다른 소개와 큐레이션을 가져야 하며 카테고리 목록의 단순 복제본이 아니어야 한다.

## 6. 카테고리 상세 `/categories/[category]/`

- 카테고리 이름과 고유 설명
- 대표 글 또는 입문 글
- 최신순 글 목록
- 페이지네이션
- 관련 주제 허브 링크

## 7. 태그 목록 및 상세

### `/tags/`

- 태그의 용도 안내
- 글 수가 있는 태그 목록
- 이름 또는 사용 빈도 기준 정렬

### `/tags/[tag]/`

- 태그 이름과 필요한 경우 설명
- 해당 태그의 게시물 목록
- 관련 태그

콘텐츠가 지나치게 적은 태그 상세 페이지는 생성하지 않거나 noindex 처리한다.

## 8. 검색 `/search/`

- 검색 입력과 제출 버튼
- 검색 결과 수
- 제목, 설명, 분류, 날짜가 포함된 결과
- 검색어가 없거나 결과가 없을 때의 안내
- 키보드 및 스크린 리더용 상태 메시지

검색 결과는 기본적으로 noindex 처리하며, 핵심 검색 기능은 외부 서비스 장애 시에도 사이트 탐색을 막지 않아야 한다.

## 9. 소개 `/about/`

- 운영자 소개와 전문 분야
- 블로그의 목적과 다루는 주제
- 실제 경험과 검증 방식
- 이해관계 및 독립성 원칙 요약
- 편집 원칙, 제휴 고지, 연락처 링크

## 10. 편집·리뷰 원칙 `/editorial-policy/`

- 주제 선정 기준
- 작성, 사실 확인, 수정 절차
- 제품 리뷰 테스트 방법과 평가 원칙
- AI 도구 사용 여부와 검토 원칙
- 협찬과 광고가 평가에 영향을 주지 않는다는 원칙
- 오류 제보와 정정 정책
- 문서 시행일과 최종 수정일

## 11. 광고·제휴 고지 `/affiliate-disclosure/`

- 광고와 제휴 링크의 의미
- 수수료 발생 방식
- 제품 제공 및 협찬 표시 방식
- 평가의 독립성 원칙
- 문의 방법
- 시행일과 최종 수정일

## 12. 개인정보 및 쿠키 정책

### `/privacy/`

- 수집 항목과 수집 방법
- 이용 목적과 보관 기간
- 분석, 광고, 문의 처리 등 제3자 서비스
- 이용자 선택권과 문의 방법
- 시행일과 최종 수정일

### `/cookies/`

- 필수, 분석, 광고 쿠키의 구분
- 각 제공자와 목적·기간
- 동의 변경 방법
- 브라우저 설정 안내

실제 사용하는 서비스가 정해진 뒤 그 서비스의 동작과 계약 조건에 맞게 법률 검토한다.

## 13. 연락 `/contact/`

- 연락 가능한 주제
- 공개 이메일 또는 보호된 문의 수단
- 답변 예상 범위
- 개인정보 안내

정적 사이트 초기 버전은 외부 폼 없이 이메일 링크만 제공할 수 있다.

## 14. 404 `/404.html`

- 찾을 수 없다는 명확한 메시지
- 홈, 전체 글, 검색 링크
- 주요 주제 링크
- 실제 HTTP 404 응답

## 15. 반응형 원칙

- 모바일은 단일 열을 기본으로 한다.
- 데스크톱에서는 본문 가독성을 유지하는 최대 너비와 선택적 목차 열을 사용한다.
- 터치 대상은 충분한 크기와 간격을 확보한다.
- 표와 긴 코드 블록은 페이지 전체가 아니라 해당 영역 안에서 가로 스크롤한다.
- 광고, 이미지, 임베드가 작은 화면에서 본문을 넘지 않아야 한다.

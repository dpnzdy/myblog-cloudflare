# 사이트맵

## 1. 정보 구조

```text
/
├── /posts/                         전체 글
│   └── /posts/[slug]/              게시물 상세
├── /categories/                    카테고리 목록
│   └── /categories/[category]/     카테고리별 글
├── /tags/                          태그 목록
│   └── /tags/[tag]/                태그별 글
├── /reviews/                       IT 제품 리뷰 허브
├── /ubuntu/                        Ubuntu 주제 허브
├── /python/                        Python 주제 허브
├── /codex/                         Codex 주제 허브
├── /search/                        사이트 검색
├── /about/                         운영자 소개
├── /editorial-policy/              편집·리뷰 원칙
├── /affiliate-disclosure/          광고·제휴 고지
├── /privacy/                       개인정보 처리방침
├── /cookies/                       쿠키 정책
├── /contact/                       연락 방법
├── /rss.xml                        RSS 피드
├── /sitemap-index.xml              XML 사이트맵 진입점
├── /robots.txt                     크롤링 정책
└── /404.html                       찾을 수 없는 페이지
```

실제 사이트맵 파일명은 Astro 통합 기능과 Cloudflare Pages의 출력 방식에 맞춰 확정한다. 위 경로는 논리적 계약이다.

## 2. 전역 내비게이션

### 헤더

- 로고 또는 사이트명: 홈
- 리뷰
- Ubuntu
- Python
- Codex
- 전체 글
- 검색
- 테마 전환

### 푸터

- 소개
- 편집·리뷰 원칙
- 광고·제휴 고지
- 개인정보 처리방침
- 쿠키 정책
- 연락처
- RSS
- 저작권 및 사이트 운영 정보

## 3. 분류 원칙

- 카테고리는 글의 대표 주제 하나만 지정한다.
- 초기 카테고리는 `reviews`, `ubuntu`, `python`, `codex`로 제한한다.
- 태그는 제품명, 기술명, 버전, 사용 목적처럼 횡단 탐색에 필요한 속성에 사용한다.
- 의미가 겹치는 태그는 별칭을 만들지 않고 대표 표기로 통합한다.
- 주제 허브는 단순 최신 글 목록이 아니라 주제 소개, 입문 순서, 핵심 글, 최신 글을 제공한다.

## 4. 색인 정책

| 페이지 유형 | 기본 색인 | 사이트맵 | Canonical | 비고 |
|---|---:|---:|---|---|
| 홈 | 예 | 예 | 자기 자신 | 사이트 대표 페이지 |
| 게시물 상세 | 예 | 예 | 자기 자신 | 초안 제외 |
| 전체 글 및 주제 허브 | 예 | 예 | 자기 자신 | 고유 설명 필요 |
| 카테고리 상세 | 예 | 예 | 자기 자신 | 글이 충분할 때 공개 |
| 태그 상세 | 조건부 | 조건부 | 자기 자신 | 얇은 페이지는 비공개 또는 noindex |
| 검색 결과 | 아니요 | 아니요 | 검색 기본 URL | noindex, follow |
| 페이지네이션 | 조건부 | 예 | 각 페이지 자기 자신 | 중복 없는 목록 구성 |
| 정책·소개 페이지 | 예 | 예 | 자기 자신 | 신뢰 정보 제공 |
| 404 | 아니요 | 아니요 | 없음 | 실제 404 상태 필요 |
| 초안 | 아니요 | 아니요 | 없음 | 프로덕션에서 경로 미생성 |

## 5. URL 규칙

- 소문자 영문, 숫자, 하이픈만 사용한다.
- 날짜를 URL에 넣지 않아 수정과 갱신에 유연하게 대응한다.
- 게시물은 `/posts/[slug]/`를 영구 주소로 사용한다.
- 카테고리와 태그의 표시명은 한국어일 수 있으나 경로 키는 안정적인 영문 슬러그를 사용한다.
- 후행 슬래시 정책은 사이트 전체에서 하나로 통일한다.
- 쿼리 매개변수는 검색, 추적 등 필요한 경우에만 사용하고 canonical에서 제거한다.

## 6. 향후 확장

- 다국어 도입 시 `/ko/`, `/en/` 같은 언어 경로와 hreflang을 추가한다.
- 작성자가 늘면 `/authors/[author]/`를 추가한다.
- 리뷰가 충분히 축적되면 제품군별 비교 허브와 브랜드 허브를 추가한다.
- 뉴스레터를 도입하면 구독 확인, 완료, 해지 페이지를 추가한다.
